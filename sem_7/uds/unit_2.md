## Error prevention vs Error recovery

### Error prevention

- prevents error **before** happening
- avoids mistakes
- before or during user action
- does so by using constraints, suggestions, good defaults, confirmatio
- phone num does not allow alphanum characters
- reduce chance of incorrect actions

### Error recovery

- helps user identify and fix an error after it occurs
- recover quickly from mistakes
- **after error** has occured
- clear error messages, explainations and solutions
- invalid num entered → enter valid 10 digit number
- helps understnad the problem

## Heuristic Evaluation vs User Testing

### Heuristic Evaluation

- usabilty experts perform this
- experts inspect interface
- find violations of usabilty principles
- eg: expert notices that website gives no feedback after clicking submit
- can identify problems without recruiting users
- limitation: experts may identfy issues that users dont experience

#### Defination

usabilty method in whicch evaluators inspect an interface
identifyt usabilty problems
by checking against establishbed usabilty heuristics

#### Purpose

1. identify usabilty problem
2. determine which usabilty heuristic is violated
3. assign Severity rating
4. rovide reccomendation for improving

### User Testing

- real users perform this
- actual user behaviour / difficulties
- users perform predefined tests
- observe actual usabilty
- eg: user clicks submit, gets no feedback becomes confused
- shows how real users actually interact
- limitation: requres particpants and testing

## Severity Ratings

- estimates how serious a usability problem is
- it considers factors like:
  - frequency
  - impact
  - persistence

### Nielsen's 0-4 Severity Scale

- 0 → not a problem
- 1 → cosmetice problem (small alignment issues etc)
- 2 → Minor usabilty problem (annoying but does not prevent task completion)
- 3 → major usabilty problem (frustrating)
- 4 → usabilty catastraphe (banking system causes user to pay wrong amount)

## Microinteraction

- small, focused interaction in a UI
- that provides feedback in response to user action / change in state
  **(trigger / feedback pair)**

### Example - Pull to refresh

- user action (trigger) → refresh animation appears (feedback) → new contentiloads
- this gives immediate visual feedback
- that the refresh action has been recognized
- scrollbar, digital alarm, swipe animation, email notification
